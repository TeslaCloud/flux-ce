    announce(message)
    Prints a line that stands out, prefixed with the version and the name of the migration.
    change()
    Describes the schema changes of the migration. Meant to be overridden. The statements used in here are reverted automatically when the migration is rolled back, as long as they are reversible: create_table, add_column, rename_column, add_index, add_foreign_key, add_reference, add_timestamps and their counterparts are. For the rest, use #reversible or define #up and #down instead.
    display_name()
    Returns the name used in the console output: the camel-cased name of the migration file, or the class name.
    down()
    Reverts the migration. Reverts #change by default.
    exec_migration(direction) internal
    Runs the migration's #change, or #up / #down if #change is not overridden.
    execute_block(callback)
    Runs a function. When the migration is being reverted through its #change, the function is recorded like a statement and run in its turn.
    has_change()
    Checks whether the migration overrides #change.
    init(version)
    Creates a migration. A migration file defines a migration, describes its changes in #change (or in #up and #down) and returns it. The version and the name of the migration come from its file name, '<version>_<name>.lua'.
    is_verbose()
    Checks whether the migration prints its progress.
    migrate(direction)
    Runs the migration in the given direction, printing what happens.
    reversible(callback)
    Lets #change run code that differs between migrating and reverting. The helper that the callback receives runs its 'up' function only when migrating and its 'down' function only when reverting.
    revert(callback)
    Runs the inverse of the statements made inside of the function. Normally used inside of #change to undo what an earlier migration did.
    reverting()
    Checks whether the migration is being reverted at the moment.

    suppress_messages(callback)
    Runs a function without printing anything.
    up()
    Applies the migration. Runs #change by default; override it together with #down for migrations that cannot be described by a reversible #change.

    ActiveRecord.Migration:init(version)

    packages/active_record/lib/migrator/migration.lua:31

    Creates a migration. A migration file defines a migration, describes its changes in #change (or in #up and #down) and returns it. The version and the name of the migration come from its file name, '<version>_<name>.lua'.

    -- db/migrate/20190309120000_add_role_to_users.lua
local AddRoleToUsers = ActiveRecord.Migration.new()

function AddRoleToUsers:change()
  add_column('users', 'role', 'string', { default = '\'user\'' })
end

return AddRoleToUsers

    ActiveRecord.Migration:reversible(callback)

    packages/active_record/lib/migrator/migration.lua:178

    Lets #change run code that differs between migrating and reverting. The helper that the callback receives runs its 'up' function only when migrating and its 'down' function only when reverting.

    function Migration:change()
  reversible(function(dir)
    dir:up(function() execute("UPDATE users SET role = 'user'") end)
    dir:down(function() execute("UPDATE users SET role = NULL") end)
  end)
end

    Parameters

    • callback Function receives the direction helper
